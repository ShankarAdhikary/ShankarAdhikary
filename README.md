I am a cybersecurity student focused on understanding how systems fail, validating weaknesses responsibly, and communicating technical findings clearly. I build practical skills through security labs, CTFs, coursework and hands-on projects.

- **Break it** — study web application weaknesses, authentication and authorization logic, network exposure and common misconfigurations in authorised environments.
- **Automate it** — use scripting to reduce repetitive work in reconnaissance, analysis and security workflows.
- **Prove it** — reproduce findings, preserve evidence and distinguish confirmed issues from false positives.
- **Document it** — write clear notes and walkthroughs so the work can be understood and repeated.

All testing is limited to systems, labs and programs where I have permission.

## `03 — OPERATING PROCEDURE`

| PHASE | WHAT HAPPENS |
|---|---|
| Scope | Confirm the target, permission, boundaries and assumptions. |
| Recon | Gather relevant passive and active information within scope. |
| Enumerate | Map services, endpoints, parameters and exposed functionality. |
| Test | Validate suspected weaknesses carefully in an authorised environment. |
| Verify | Reproduce the behaviour and eliminate false positives. |
| Document | Record steps, evidence, impact and limitations. |
| Report | Explain the finding clearly, including practical remediation. |
| Retest | Confirm whether the proposed fix resolves the issue. |
